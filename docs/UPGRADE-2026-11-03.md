## Social Risk Factor import and interpretation

`Name/Social Risk Factor(s)` is optional; both the older ten-column and updated eleven-column exports are accepted, in any column order. Literal numeric/string `0` remains raw `"0"`; blanks remain null. No punctuation splitting or interpretation is inferred. Existing hashed Member ID identity is used for profile enrichment; programme/session attendance identity does not include profile attributes.

Import preview includes existing attendance matches, new entries, duplicates, profile updates, conflicting information, missing fields, validation issues and resulting attendance/profile counts. No write happens until confirmation.

1. **Add New Records:** retains existing profiles, skips conflicting rows, deduplicates attendance.
2. **Merge and Update Existing Records** (default): adds new attendance and updates reviewed nonblank participant fields, even if every attendance row already exists. Incoming blanks/unknown placeholders preserve known profile values. Programme-domain conflicts remain skipped. Within one reviewed file, the final nonblank profile value in source row order wins; conflicting updates appear in the issue report. This is import order, not a historical assessment date.
3. **Full Replacement:** replaces attendance only; retains profiles, sessions/programmes, targets and decisions. Requires typing `REPLACE ATTENDANCE`. A database snapshot is created in the same transaction before deletion. It includes profile data and original attendance source/import fields. Changed database contents invalidate a replacement preview. Invalid/conflicting rows are excluded and shown in preview. This mode is administrative and never selected automatically based on file size.

Repeated imports do not duplicate attendance or raw risk observations. Profile raw values and import timestamps live in participant JSON; immutable `risk_observations` retain distinct participant/session/raw observations, including blanks. Codes are interpreted at report time using separately stored organisation mappings. Import timestamps do not establish historical risk assessments. An authorised blank-clearing workflow has not been introduced; correct source data or use a separately reviewed data-maintenance procedure to clear known values.

## Privacy and deliberate limits

Social Risk Analysis is a fixed **full available cohort** aggregate, independent of global filters, explicitly labelled on the page. General dashboard payloads omit raw values, mappings and risk statistics. Viewer accounts cannot retrieve risk aggregates or configuration. Risk downloads and arbitrary risk filters are blocked server-side.

The protected report checks equivalence groups across **all recorded filterable profile fields and exact delivered-session membership**. Every nonempty group must meet the privacy minimum, initially five. This protects against splitting a reported group through the application's demographic, programme or timing filters. If any group fails, all risk state/category totals, completion rates, programme slices, demographics and insights are withheld together; complementary totals cannot bypass that gate. Groups with multiple mapped factors are supported without summing overlapping categories or drawing a pie chart.

When this conservative release check passes, authorised staff can select a category and inspect programme reach rankings, sessions attended, entries per participant, repeat engagement, and gender/age/race/client/boundary/domain breakdowns from the same fixed snapshot. Engagement tables distinguish one-session from repeat participants. Completion means a mapped risk or explicitly approved no-risk classification. Transparent Review/Maintain discussion prompts require minimum session/participant evidence; low repeat attendance is not interpreted as lack of interest. These fixed-snapshot controls are deliberately restrictive, are not differential privacy, and require organisational review before broad operational use. Releasing time-varying snapshots is not a historical assessment series.

The initial `0`/blank file cannot support interpreted risk findings. Arbitrary date/audience-filtered risk charts, risk-specific targets and downloadable risk reports are not enabled. General demographic analysis remains for authenticated staff; existing aggregate display/report restrictions remain and must not be treated as an anonymisation guarantee for arbitrary demographic exploration.

Other scope limits: no free-form AND/OR segment expression builder; no stacked custom chart without a validated second series; no direct demographic-segment comparison wizard (combine filters or compare programmes/periods instead); no shared-template editing/deletion UI; no target projections; no risk history reconstruction; no individual registration history. Cost, capacity utilisation, venue/frequency/programme-type filters and genuinely new-to-centre counts need validated source fields and definitions. Existing observed recurrence describes recorded sessions, not scheduled frequency. Below-60 attendees remain in all-age attendance while senior-reach metrics and existing demographic charts use the configured senior threshold.
